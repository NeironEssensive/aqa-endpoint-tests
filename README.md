# aqa-endpoint-tests

Автотесты для сервиса из тестового задания AQA Engineer. У сервиса один эндпоинт `POST /endpoint`, который принимает действия пользователя `LOGIN`, `ACTION` и `LOGOUT` и для части из них обращается во внешний сервис (`/auth`, `/doAction`).

Стек: Java 17, JUnit 5, WireMock, REST Assured, AssertJ, Allure, Maven.

## Как запустить

Нужны JDK 17 или новее. Maven ставить не обязательно, в проекте есть Maven Wrapper.

1. Положить `internal-0.0.1-SNAPSHOT.jar` в папку `app/` в корне проекта.
2. Запустить тесты:

```bash
./mvnw clean test -Dmaven.test.failure.ignore=true
```

3. Открыть отчёт:

```bash
./mvnw allure:serve
```

На Windows вместо `./mvnw` используется `mvnw.cmd`.

Тесты сами поднимают заглушку внешнего сервиса на WireMock (порт 8888) и запускают приложение с нужными параметрами (`-Dsecret`, `-Dmock`), а после прогона всё останавливают. Лог приложения сохраняется в `target/app.log`.

Флаг `-Dmaven.test.failure.ignore=true` нужен потому, что часть тестов падает из-за найденных дефектов (список ниже), а отчёт хочется получить в любом случае.

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `app.jar` | `app/internal-0.0.1-SNAPSHOT.jar` | путь к jar приложения |
| `app.url` | `http://localhost:8080` | адрес приложения |
| `app.start` | `true` | `false`, если приложение уже запущено вручную |
| `api.key` | `qazWSXedc` | значение заголовка `X-Api-Key` |
| `mock.port` | `8888` | порт заглушки внешнего сервиса |

Если приложение запускается вручную (`-Dapp.start=false`), его нужно стартовать с `-Dmock=http://localhost:8888/`, иначе запросы не дойдут до заглушки.

## Что проверяется

- Доступ по API-ключу: запросы без ключа и с неверным ключом отклоняются для всех действий и не доходят до внешнего сервиса.
- LOGIN: успешный вход, формат запроса в `/auth`, повторный вход, поведение при ошибках, недоступности и долгом ответе внешнего сервиса. После неудачного входа токен не должен сохраняться.
- ACTION: действие после входа, формат запроса в `/doAction`, действие без входа и с чужим токеном, ошибки внешнего сервиса. Ошибка внешнего сервиса не должна завершать сессию.
- LOGOUT: выход, недоступность действий после выхода, повторный вход, выход без входа, независимость сессий разных пользователей. Внешний сервис при выходе не вызывается.
- Валидация: длина и состав токена, допустимые значения `action`, запросы без параметров, некорректные HTTP-запросы.
- Сценарии: полный цикл вход - действия - выход, одновременные запросы на вход с одним и с разными токенами.

Коды ошибок в документации не описаны, поэтому для отказов (400, 401, 403, 409) тесты фиксируют текущее поведение сервиса. Для сбоев внешнего сервиса проверяется только то, что запрос завершился ошибкой с `"result": "ERROR"`.

В позитивных сценариях токены генерируются из символов `0-9A-F`. Так дефект с буквами `G-Z` (см. ниже) проявляется только в отдельных тестах на состав токена и не роняет случайным образом остальные.

## Найденные дефекты

1. **Токены с буквами G-Z отклоняются.** По документации токен состоит из 32 символов `A-Z0-9`, но сервис принимает только `0-9A-F` и на токен вроде `GHIJ...` отвечает 400 с сообщением `token: должно соответствовать "^[0-9A-F]{32}$"`. Тесты: «Токен из допустимых символов принимается: только буквы G-Z» и «...: буквы A-Z и цифры вперемешку».
2. **Ошибки клиента возвращаются как 500 Internal Server Error.** Запрос методом GET или PUT, тело в JSON вместо формы, обращение по несуществующему адресу - во всех случаях сервис отвечает 500, хотя ожидаются коды 4xx (405, 415, 404). Тесты группы «Некорректный HTTP-запрос».

Ещё два замечания, которые видны при работе с сервисом, но тестами не закреплены, так как документация их явно не описывает:

- При неверном API-ключе приложение пишет в лог правильный ключ: `Authentication failed: invalid api secret. Expected: 'qazWSXedc' Actual: '...'`. Секрет не должен попадать в логи.
- Ответ внешнего сервиса с кодом 3xx (например, 302) приложение считает успешным: вход проходит, токен сохраняется.

## Структура

```
src/test/java/ru/qa/endpoint
├── checks   проверки ответа сервиса
├── client   клиент для /endpoint
├── config   параметры запуска
├── data     генерация токенов
├── env      запуск приложения и заглушки на время прогона
├── mock     заглушка внешнего сервиса на WireMock
└── tests    тесты
```
